# GyroVR 차량 제어와 연출 제작

지니소프트의 GCC사관학교 3기 기업연계 프로젝트에서 차량 경로 추종 기능과 추격 장면 제작을 맡았습니다. Blueprint 주행 로직을 C++ 플러그인으로 분리하고, 아트팀이 스플라인에서 속도를 편집할 수 있도록 도구를 만들었습니다. 이후 시퀀서에서 차량의 등장과 추월, 충돌 후 이탈을 구성하며 최종 장면에 적용했습니다.

정리한 작업 기록은 8월 3일부터 9월 30일까지입니다. 완성 영상은 팀 결과물이며, 이 글은 제가 담당한 차량 제어와 연출 작업을 설명합니다.

## 차량 움직임과 연출 요구

초기에는 스플라인 반복 주행과 추적 카메라를 Blueprint로 구현했습니다. 차량을 경로에 직접 고정하면 움직임이 기계적으로 보였고, 물리 주행을 사용하면 원하는 순간에 차량을 배치하고 접촉 장면을 맞추는 데 조정이 필요했습니다.

주행 기능을 재사용할 수 있게 정리하는 일과, 제작 중인 장면의 타이밍을 맞추는 일을 함께 진행했습니다. 물리 기반 제어, 레일 이동, 하이브리드 방식을 검토·시험했고, 9월에는 주행 애니메이션을 시네마 차량·시퀀서 방식으로 전환했습니다.

## C++ 플러그인과 모드 구성

레퍼런스 프로젝트를 최신 엔진 버전으로 업그레이드한 뒤, Blueprint 로직을 C++로 옮겨 `SplineFollowVehicle` 플러그인으로 분리했습니다. 사용 문서를 작성해 아트팀에 전달하고 테스트했습니다.

목표 속도를 따라가는 제어와 km/h 변환을 추가했습니다. 차량의 최고 속도가 제한되는 구간은 이동 컴포넌트의 RPM 설정을 확인해 조정했습니다. 경로가 겹칠 때 지나온 구간이나 다른 커브를 목표로 선택하는 문제는 진행 거리 기준으로 해결했습니다. 좌우 조향이 반복되며 궤적이 물결치는 현상은 속도에 따라 목표점 거리를 조절해 개선했습니다.

모드마다 이동 방식이 달라 자동차·레일·드론의 Follow 컴포넌트를 구분하고, 마스터 컴포넌트는 전환 순서를 관리하도록 설계했습니다. 레일 전용 속도값을 분리하고, 지정한 스플라인 포인트에서 레일 모드로 전환하도록 구현했습니다. 드론 모드는 후속 구현 작업을 진행했으며, 모든 전환 조합의 완료를 이 글의 성과에 포함하지는 않았습니다.

## 속도 편집과 에디터 도구

경로의 시작·끝에 기본 속도 마커를 자동 생성하고 중간 마커로 구간 속도를 지정하도록 구성했습니다. 잘못된 위치와 중복 마커 저장을 막고 시작·끝 마커를 보호했습니다. 구간 속도를 보간해 전체 이동 시간과 시간별 거리·진행률·속도를 계산했습니다.

스플라인 포인트와 속도 마커가 별도 데이터라 포인트를 편집해도 마커가 따라오지 않는 문제가 있었습니다. 연결 마커와 독립 마커를 구분해 관계를 정리하고 루프 구간 동기화 오류를 수정했습니다. 에디터 유틸리티 위젯으로 즉시 프리뷰를 구현했으며, 속도 마커를 스플라인 위에서 확인하도록 시각화했습니다.

Details UI를 확장할 때는 시네마 스플라인의 기본 UI까지 덮어써지는 문제가 생겼습니다. 기본 UI를 유지한 뒤 마커 UI만 덧붙이는 방식으로 수정했습니다.

## 실행 상태를 따라가며 수정한 오류

레일에서 자동차 모드로 복귀하면 바퀴 본과 서스펜션이 비정상적으로 보였습니다. 콜리전을 해제하는 과정에서 물리 상태가 재생성되는 것이 원인임을 확인해 해결했고, 해당 작업과 사용 문서를 플러그인 v0.1.2에 반영했습니다.

닫힌 경로에서는 첫 주행이 끝난 뒤 두 번째 주행부터 모드 전환이 멈추기도 했습니다. 마지막 전환을 소비한 컴포넌트가 스스로 Tick을 종료하고 있었습니다. 닫힌 루프에서는 Tick을 유지하도록 수정했습니다.

경로 이탈·전복·진행 정체를 구분해 리타이어 판정과 리스폰도 구현했습니다. 리스폰 뒤 같은 장애물에 반복해서 막히는 현상은 경로 일부를 건너뛰도록 처리해 완화했습니다.

## 시퀀서에서 구성한 추격 장면

추격차 7대의 거리 키와 차선을 조정해 등장·추월 흐름을 구성했습니다. 히어로 이동 거리에 맞춰 코너 감속과 탈출 가속을 맞추고, 차량 간 접촉 간격과 회복 타이밍을 점검했습니다. 젤리곰에 맞아 날아가는 반동, 급하강 구간 이탈, 벽타기 추월 등 장면별 움직임도 수정했습니다.

차량 BP에 라인 트레이스 높이 보정을 넣고, 대기 중 차량이 회전하는 문제는 출발 전 룩어헤드 값을 0으로 설정해 수정했습니다. 네 바퀴의 노면 높이 보정과 노면 선택을 개선하며 차체 관통과 바퀴 부양을 검수했습니다. Animation Blueprint의 Modify Bone으로 서스펜션을 조절하는 방식은 별도로 시험했습니다.

접촉 키는 323개에서 100개로 줄여 트랙을 정리했습니다. 이는 편집 키 수를 정리한 결과이며, 런타임 성능 측정값으로 사용하지 않습니다.

## 경로 변경과 작업 자동화

히어로 경로 변경과 잘못 저장된 거리 키로 차량 이동이 어긋났을 때, 원인을 확인하고 임시 복구했습니다. 차량별 등장·추월 순서와 몸싸움 장면을 표로 정리해 스플라인 재구축 기준을 마련했습니다.

Unreal Python으로 추격차 7대의 스플라인과 시퀀서 거리 키를 다시 적용했습니다. 옛 접촉 섹션 21개를 비활성화하고, 플레이 테스트로 속도와 차 간격을 확인했습니다. 이후 주요 12장면을 스토리보드로 정리하고, 연출 마커 11개와 이벤트표를 추가했습니다.

## 캐릭터 반응과 리그 작업

초기에는 고정형 GyroVR 리그에서 액터의 최종 회전값을 Yaw·Pitch·Roll 피벗에 매핑했습니다. 3축 링과 3인 좌석 형태의 디버그 프록시로 에디터 스크럽과 PIE에서 회전 방향을 확인했습니다. 이 작업은 실제 장비 통신 구현과 구분합니다.

9월 말에는 Blender에서 운전 대기·돌아보기·도발·피격 동작을 제작하고, 캐릭터 7명을 시퀀서에 배치해 FBX 애니메이션을 적용했습니다. Animation Blueprint의 표정·시선·차량 관성 반응을 연동해 시험했습니다.

## 작업에서 배운 점

연출용 차량은 자연스럽게 달리는 것과 정해진 순간에 특정 위치에 도착하는 것을 함께 요구했습니다. 물리값 조정만으로 해결하기 어려운 부분은 이동 방식과 시퀀서 제어를 다시 검토했습니다. 도구를 만들 때도 경로·마커·거리 키의 편집 관계를 먼저 정리해야 이후 변경을 다룰 수 있다는 점을 배웠습니다.

차량 BP 전체를 C++로 이전하려던 9월 17일 작업은 시험 후 중단했습니다. 8월의 주행 플러그인 C++ 전환과 별개의 작업입니다. 완료한 기능과 시도에 그친 작업을 구분해 설명합니다.
